## 问题背景

原理图评审中有一类问题适合自动检查：LDO 输入/输出是否连接了合理的去耦电容、TVS/ESD 器件是否连接到受保护网络和地、元件参数是否达到预设阈值。KiCad 网表提供了元件、引脚和网络关系，可以作为静态分析入口。

## 解析与建模

工具需要同时处理 KiCad S-expression 和 XML 网表。解析后，将数据归一化为三类核心实体：

- 元件及其引用标号、数值和属性；
- 元件引脚；
- 网络以及连接到该网络的引脚集合。

在此基础上把网表看作一张连接图，通过元件引脚到网络、网络到相邻元件的查询执行规则检查。Pydantic 用来校验输入和输出模型，避免接口层传播结构不一致的数据。

## 电源规则检查

- **LDO 去耦**：识别输入、输出和地引脚，查找相邻电容，并检查容量阈值。
- **TVS/ESD**：检查器件是否跨接受保护的网络和参考地连接。
- **结果边界**：参考标号和值只能提供启发式线索，不能代替器件数据手册与人工原理图评审。

## JSON-RPC 与 MCP

JSON-RPC 将解析和检查能力封装为稳定的方法调用；FastMCP 让支持 MCP 的 Agent 可以发现并调用这些分析工具。两者解决的是“如何调用”，不会自动提高规则本身的正确性。
